올해 상반기는 Upstage Ambassador 활동을 하고 있습니다 감사하게도 이번 활동에서 우수 Ambassador 로 선정되었습니다. 돌아보면 가장 기억에 남는 경험은 전남대학교에서 스킬톤을 열었던 일입니다.

스킬톤은 Upstage API 를 활용해 일상생활의 문제를 해결하는 에이전트용 스킬을 만드는 해커톤이었습니다. 사전 교육, 예선, 스크리닝, 본선까지 이어지는 과정이 있었고, 전남대학교 교수님들, 후배분들, 그리고 Upstage 교육팀 분들의 도움 덕분에 무사히 마무리할 수 있었습니다.

처음으로 해커톤을 기획하고 운영하며 여러 사람 사이에서 일정과 의견을 조율했고, 스킬톤 사전 교육에서는 스킬과 에이전트에 대한 교육도 직접 진행했습니다. 이 과정에서 가장 많이 고민했던 것은 서로에게 가치가 남는 경험을 만드는 일이었습니다. 참가하는 학생들에게는 실제로 기술을 써보는 경험이 남고, 함께 운영한 분들과는 행사를 끝까지 완주해낸 경험이 남고, 저에게는 배운 것을 다시 전달하며 성장하는 시간이 되기를 바랐습니다. 물론 생각처럼 매끄럽게 흘러가지 않은 순간도 많았습니다. 그래도 그 과정 덕분에 기술을 이해하는 일과, 여러 사람과 함께 하나의 경험으로 만들어내는 일은 전혀 다른 난이도의 일이라는 것을 배웠습니다.

2 주가 1 년처럼 느껴질 만큼 빠르게 변화하는 요즘, 제가 배우고 전달했던 것들 중 많은 것은 금방 outdated 될지도 모릅니다. 그래도 교육 때 에이전트를 실습하고, 스킬을 직접 사용해보고, 질문을 받고, 운영 환경을 고민했던 경험은 오래 남을 것 같습니다. 예선과 본선에서 교육 때 만났던 학생들을 다시 보게 된 것도 좋았습니다. 교육 중에는 빠르게 변하는 도구들도 결국 단단한 기본기 위에서 동작한다는 이야기를 하고 싶었습니다. 교육을 준비하며 Claude Code 같은 에이전트가 스킬을 호출하는 방식 안에도 lazy loading, caching 같은 CS 개념이 녹아 있고, 많은 도구가 바뀌더라도 그 밑단에서 동작하는 원리와 사고방식은 오래 남는다고 느꼈습니다.

이번 스킬톤에서 중요하게 고려했던 것 중 하나는 “실제로 실행 가능한가”였습니다. Skill 이라는 이름을 붙이려면 단순한 아이디어나 문서에서 끝나는 것이 아니라, Agent 환경에서 반복적으로 재사용되고 의도한 동작을 수행할 수 있어야 한다고 생각했습니다. 그래서 학부생 스크리닝 팀을 구성해 제출된 스킬들을 함께 실행해보고, 에러를 확인하고, 계획서와 실제 동작이 얼마나 일치하는지 검토했습니다. 주말에 밤을 지새우며 테스트하고 진행 상황을 확인하는 과정이 쉽지는 않았지만, 꽤 낭만적인 시간이기도 했습니다. 의도가 담기는 스킬의 특성상 사람마다 해석이 달라질 수 있기 때문에, 실행 결과를 기준으로 한 validation 이 필요하다고 봤습니다.


작년 한 해는 내가 정의한 문제를 어떻게 거인들의 어깨 위에서 풀 수 있을지를 고민하는 시간이 많았습니다. 올해의 절반이 지나가는 지금은 내가 배운 것을 어떻게 다른 사람에게 잘 전달할 수 있을지를 고민하는 시간이 많았습니다. 배움을 다시 전달하는 일은 생각보다 어려웠습니다. 하지만 동시에 큰 기쁨도 있었습니다.


Ambassador 활동을 하며 Upstage API 를 활용해 제 Obsidian plugin 에 embedding 로직을 구현해보기도 하고, Solar 를 에이전트에 넣어 테스트해보기도 했습니다. 개인적으로는 에이전트가 API 를 어떻게 호출하는지, context length 나 호출 제한 같은 운영상의 제약이 실제 동작에 어떤 영향을 주는지도 더 구체적으로 체감할 수 있었습니다.  
 좋은 기회를 주신 Upstage 와 함께해주신 모든 분들께 감사드립니다.
